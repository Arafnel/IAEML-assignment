### Описание экспериментального сетапа и RL-модели

Для решения задачи автономной навигации роботакси в 2D с динамическими и статическими препятствиями был применен PPO (Proximal Policy Optimization) с архитектурой Actor-Critic, реализованный на библиотеках JAX, Equinox и Optax

#### Пространство наблюдений и действий
* Вход (Observation Vector): плоский вектор размерности 68, объединяющий скалярное расстояние до оптимальной траектории (1), единичный вектор направления пути (2), расстояния с 32 лидарных лучей в координатах (x, y) (64) и текущую линейную скорость автомобиля (1)
* Выход (Continuous Action Space): двумерный вектор непрерывных действий $a = [a_{\text{accel}}, a_{\text{steer}}] \in [-1, 1]^2$, управляющий ускорением и углом поворота руля

#### Архитектура нейросети и алгоритм
* Сеть Actor (политика): многослойный перцептрон (eqx.nn.MLP) с двумя скрытыми слоями по 64 нейрона и функцией активации tanh. Выдает вектор математических ожиданий $\mu_\theta(s)$ (ограниченный через tanh), который вместе с параметром стандартного отклонения $\sigma = \exp(\text{log\_std})$ задает многомерное нормальное распределение $\mathcal{N}(\mu_\theta(s), \sigma^2)$ для exploration. На этапе инференса (eval_mode=True) используется детерминированное среднее $\mu_\theta(s)$
* Сеть Critic (оценщик ценности): отдельный MLP с аналогичной архитектурой, предсказывающий скалярную функцию ценности состояния $V_\phi(s)$
* Функция потерь PPO и GAE: для снижения дисперсии градиентов используется оценка преимущества GAE (Generalized Advantage Estimation) с параметрами $\gamma = 0.99$ и $\lambda = 0.95$. Целевая функция включает суррогатный лосс актора с клиппингом ($\epsilon = 0.2$), квадратичную ошибку критика ($c_1 = 0.5$) и энтропийный бонус ($c_2 = 0.01$) для предотвращения преждевременной сходимости:

$$
L^{\text{CLIP}}(\theta) = \hat{\mathbb{E}}_t \left[ \min\left( r_t(\theta)\hat{A}_t, \; \text{clip}(r_t(\theta), 1 - \epsilon, 1 + \epsilon)\hat{A}_t \right) \right]
$$

#### Основные гиперпараметры обучения
* Количество параллельных сред (`NUM_ENVS`): `64`
* Длина роллаута (`NUM_STEPS`): `128` шагов (итого `8192` транзишна за одно обновление)
* Количество итераций обновления (`TOTAL_UPDATES`): `400`
* Количество эпох PPO (`PPO_EPOCHS`): `4` с размером мини-батча `256`
* Оптимизатор: `optax.adam` ($\text{lr} = 3 \times 10^{-4}$) с глобальным клиппингом градиентов (`max_norm = 0.5`)


### 2. Вычислительные оптимизации

Для достижения высокой скорости обучения без использования тяжелых внешних фреймворков были применены функциональные трансформации JAX:

1. jax.vmap: функции env.reset и env.step векторизованы по батчу из 64 независимых сред. Позволяет собирать тысячи шагов опыта параллельно в виде единых матричных операций
2. jax.lax.scan + @jax.jit: весь цикл сбора траекторий, обратный проход для вычисления GAE (reverse=True), а также проходы по эпохам и мини батчам реализованы через jax.lax.scan внутри единой скомпилированной функции update_step. Это полностью устраняет накладные расходы интерпретатора Python во время тренировки
3. eqx.partition / eqx.combine: Для корректного проброса нейросети через jax.lax.scan статическая структура графа (функции активации) отделялась от обучаемых JAX-массивов, что позволило XLA-компилятору эффективно оптимизировать память
4. Advantage Normalization: Внутри каждого мини батча значения $\hat{A}_t$ нормализуются (вычитание среднего и деление на стандартное отклонение), что стабилизирует градиентные шаги и ускоряет сходимость


### 3. Возникшие трудности и их решение

В ходе обучения RL-агента пришлось решить следующие проблемы:

1. При попытке передавать объект модели ActorCritic напрямую внутри состояния carry цикла jax.lax.scan возникала ошибка `TypeError: Argument '<PjitFunction of <function tanh>>' is not a valid JAX type`, так как JAX пытался трактовать функцию активации как тензор. Проблема была решена применением eqx.partition перед входом в scan и eqx.combine при вызове модели
2. На ранних этапах при слабом штрафе за бездействие агент предпочитал останавливаться на траектории, чтобы избежать риска столкновения со стеной. Добавление плотной награды за проекцию скорости на вектор пути ($0.5 \cdot (\vec{d}_{\text{agent}} \cdot \vec{d}_{\text{path}}) v_t$) и небольшого штрафа за время заставило модель активно двигаться к финишу. В результате Mean Step Reward выросла с -0.29 на 25-й итерации до +2.94 к концу обучения
3. Из-за запуска скриптов из разных рабочих директорий (src/algorithms/ и src/) возникали ошибки поиска файла весов `FileNotFoundError`. Проблема устранена переходом на построение относительных путей через os.path.dirname(__file__)
